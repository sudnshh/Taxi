# 🚕 تكسي وين — نسخة الواجهات المستقلة

## شنو الجديد؟
- واجهة **الزبون** (`customer.html`): حقول «من وين؟ / لوين؟»، البحث أو التحديد من خريطة Leaflet، سعر الرحلة، كود خصم، وتتبع حالة الرحلات.
- واجهة **الكابتن** (`driver.html`): زر Online/Offline، عرض الطلبات فقط عند الاتصال، وأخذ الرحلات وإكمالها.
- واجهة **الإدارة** (`admin.html`): إدارة حسابات الكباتن والرحلات وإنشاء أكواد الخصم وتفعيلها وإيقافها.
- لكل دور **صفحة دخول مستقلة** برابط خاص، مع فحص الصلاحيات عبر Supabase. كلمة المرور والجلسة مشتركة عبر نفس الدومين إذا فتحت الأدوار بنفس المتصفح؛ استعمل نافذة خاصة مختلفة لتجربة عدة حسابات.

## روابط الصفحات بعد النشر على Railway

| الدور | رابط تسجيل الدخول | رابط الواجهة بعد الدخول |
|---|---|---|
| الزبون | `/customer-login.html` | `/customer.html` |
| الكابتن | `/driver-login.html` | `/driver.html` |
| الإدارة | `/admin-login.html` | `/admin.html` |

الصفحة الرئيسية `/` تعرض البوابات الثلاث. الرابط القديم `login.html?role=driver` وغيره يوجّه تلقائياً إلى بوابة الدخول الجديدة، حفاظاً على الروابط القديمة.

## مهم جداً: تحديث قاعدة البيانات

**على مشروع Supabase موجود وفيه حسابات ورحلات:** شغّل `upgrade.sql` فقط من Supabase → SQL Editor → New query → Run.
**على مشروع Supabase جديد تماماً:** شغّل `setup.sql` أولاً ثم `upgrade.sql`.
لا تعِد تشغيل `setup.sql` على مشروع موجود بدون حاجة، لأن الملف موجّه للتهيئة الأولى.

ملف `upgrade.sql` لا يحذف حساباتك ولا رحلاتك القديمة، ويضيف بيانات اتصال الكابتن وجداول الخصومات والدوال التي تحسب السعر وتحجز المشوار. يجب نشر الملفات وتطبيق ترقية قاعدة البيانات **معاً** حتى تعمل الميزات الجديدة.

## كيف تنشر؟
1. خذ نسخة احتياطية من قاعدة Supabase ومن مشروع Railway قبل التغيير.
2. انقل **كل الملفات** من مجلد هذا المشروع إلى المستودع/الخدمة المستخدمة بالفعل في Railway، مع الحفاظ على `auth.js` و `style.css` والملفات الجديدة.
3. شغّل `upgrade.sql` في SQL Editor لمشروع Supabase الموجود.
4. تأكد أن ملفات HTML متاحة من جذر الموقع (`/customer.html` إلخ). إذا خادمك يحتاج إعداد `static files`، عدّل إعدادات الخدمة حتى يقدّم الملفات من الجذر.
5. اختبر حجز زبون، تشغيل كابتن ثم قبوله الطلب، وإنشاء كود خصم من حساب الإدارة.

### إنشاء حساب الإدارة لأول مرة
سجّل كمستخدم زبون، ثم نفّذ الأمر التالي في SQL Editor بعد استبدال الرقم:
```sql
update public.profiles set role='admin', status='active' where phone='07XXXXXXXXX';
```
ثم استخدم `/admin-login.html` بنفس رقمك وكلمة السر.

### ملاحظات تشغيل وأمان
- الكابتن يكون Online فقط إذا فعّل الزر ووصل تحديث اتصال خلال **آخر 90 ثانية**؛ تحديث الحالة كل 30 ثانية. الواجهة لا تستقبل طلبات جديدة وهو Offline، وقاعدة البيانات تمنع قبولها كذلك.
- أكواد الخصم نسبية (1–100%)، ويمكن تحديد تاريخ انتهاء وعدد استخدامات. التحقق والحساب يحدثان في قاعدة البيانات، وليس في واجهة الزبون فقط. الكود صالح للاستخدام مرة واحدة لكل زبون، ويُسترجع الاستخدام عند إلغاء الطلب قبل قبوله.
- التسعير الحالي يحتفظ بمعادلة المشروع الأصلية: **2000 دينار أساسي + 300 دينار/كم، مقرب لأقرب 250 دينار**. يمكن تعديلها من `upgrade.sql` عند الحاجة.
- **النسخة الحالية ليست نظام تشغيل إنتاجي متكامل:** حساب مسافة الطريق يُجلب من خدمة OSRM العامة ثم يُرسل للقاعدة؛ يجب التحقق منه بخدمة موثوقة من جهة الخادم لمنع التلاعب بالمسافة والتكلفة. بحث الأماكن يستخدم Nominatim العام مع حدود استخدام، ويحتاج خدمة بحث خاصة عند توسع التطبيق.
- لا توجد رسائل SMS للتحقق من رقم الهاتف أو استرجاع كلمة المرور. تعطيل Confirm email في Supabase مطلوب في إعداد المشروع الحالي (لأن الموبايل يتحول إلى بريد داخلي). يُفضّل لاحقاً إضافة مصادقة هاتف حقيقية.
- `auth.js` يحتوي فقط على مفتاح Supabase **عام**؛ لا تضع `service_role` أو أي مفتاح سري داخل ملفات الواجهة.
- النسخة المرفقة **لا تغيّر موقع Railway مباشرة**؛ تحتاج رفع الملفات وتشغيل SQL وفق الخطوات أعلاه.
